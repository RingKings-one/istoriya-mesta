# Project instructions — История места

## Project identity
This repository is for the public website "История места". It is separate from the user's larger AI System project. Do not import that system's private skills, modules, blueprints, or process documents here.

## Approved creative direction
- Brand: История места; initial city focus: Руза.
- Visual direction: Cinematic Living Atlas.
- Balance: 60% cinematic documentary film, 40% premium travel editorial.
- Palette direction: Cinematic Earth. Current provisional colors: Deep Night #181D1A, Deep Green #334D40, Warm Stone #D7C7B2, Rust #A8664B, Soft Light #E8E1D6, Stone Grey #78786C.
- Narrative arc: Intrigue → Atmosphere → Meaning → Exploration → Connection → Action.
- Strategy: 70–80% brand-first, 20–30% discovery-first.
- Principle: PURPOSE BEFORE EFFECTS.
These are established project decisions. Do not casually replace or re-litigate them.

## Working behavior
- Work autonomously through the complete agreed task. Do not stop after every small step to ask whether to continue.
- Batch findings and questions into one concise checkpoint. Ask only when a decision materially affects the concept, architecture, budget, privacy, destructive changes, or irreversible publishing.
- Make low-risk implementation decisions independently; state assumptions in the final report.
- Be a critical partner: do not agree automatically, flag risks, distinguish verified facts from assumptions, and never invent test results.
- Prefer the smallest useful solution. Do not create a second methodology or a large documentation system.

## Engineering quality
- Preserve semantic HTML, accessibility, responsive behavior, performance, and maintainability.
- Test narrow mobile layouts and iOS Safari behavior. Prevent horizontal overflow; do not hide the symptom with overflow clipping if the underlying layout is broken.
- Prefer native scrolling unless a clear requirement justifies a custom scrolling library.
- Respect prefers-reduced-motion. Avoid animation that harms readability, navigation, or device performance.
- Use real project content where available. Temporary images are placeholders and must be tracked for later replacement with selected real photography.
- Do not replace user-selected imagery or re-run old image searches unless asked.

## Repository safety
- Work on a feature branch, not directly on main, unless explicitly instructed.
- Never delete or overwrite existing user files as incidental cleanup.
- Do not add dependencies until the actual stack and need are confirmed.
- Before deployment, report what was tested and what could not be tested.
